## What's missing

CLAUDE.md's `## Documentation hierarchy` assigns every active `docs/` subtree one
of four authority tiers, so a reader can weight a file from its path alone
without opening it. Shipped by E-0034 as the first of the three layers G-0092
proposed. It does what it says, and three things a reader meets are outside what
it says.

**Root-level documents carry no tier.** The section scopes itself to `docs/`
subtrees, so seven tracked root markdown files have no authority assignment —
including `CLAUDE.md` and `README.md`, which are as binding as anything under
`docs/design/`. `README.md` is already named in `aiwf.yaml`'s `docs.paths`, so
the kernel scans it as authoritative material for the id rules while the
hierarchy does not mention it. The two surfaces disagree about the same file
today.

**There is no vocabulary for a derived document.** `ROADMAP.md` is tracked and
regenerated by `aiwf render roadmap`; `STATUS.md` and `WHITEBOARD.md` are
gitignored and regenerated; `CHANGELOG.md` is append-only by convention. A
contradiction inside any of them is a stale render rather than a claim about the
project, so reading them for drift produces noise at a rate set by regeneration
lag. Derived is orthogonal to the four tiers — a generated file is neither
normative nor archival — and the section cannot express it.

**Nothing checks the table against the tree, and the follow-on it names is
closed.** The section states it is a fixed snapshot rather than a runtime
drift-check, and attributes that follow-on to
[G-0092](archive/G-0092-no-documented-doc-authority-hierarchy.md). G-0092 is
`addressed`: its layer 1 shipped, and the `aiwf check` rule for normative-tree
drift was marked out of scope inside it. A sentence that reads as tracked is not.

## Why it matters

The tiering is now load-bearing rather than advisory. Any review pass that audits
a specification against what the project has committed to must decide which
documents carry authority, and the tier is the only mechanism that answers it —
so a document the tiering cannot classify is one such a pass either sweeps as
though it were binding, or misses entirely.

The fact has already forked once. Scoping a commitments sweep required
classifying the root documents by hand — hand-authored against derived against
append-only — and that classification is now written into
[`docs/initiatives/milestone-preflight-as-independent-review.md`](../../docs/initiatives/milestone-preflight-as-independent-review.md)
under *Corpus and cost*, because the hierarchy could not supply it. Two places
now state what is authoritative in this repository, which is the duplication
[D-0054](../decisions/D-0054-keep-the-reasoning-derive-the-facts-record-obligations-not-events.md)
bans: when the hierarchy changes, nothing makes the second copy follow.

It will fork a third time at implementation. A shipped review pass has to tell a
reviewer what to read, and its only options are to point at a hierarchy that
omits the root files and cannot say *derived*, or to restate the classification
again.

Distinct from [G-0560](G-0560-the-normative-doc-tree-has-drifted-from-the-kernel-it-documents.md),
which is about normative documents having drifted from the kernel. This is about
documents the tiering never reaches — a defect in the classifier rather than in
what it classifies.
