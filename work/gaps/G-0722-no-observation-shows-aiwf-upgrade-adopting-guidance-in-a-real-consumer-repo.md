## What's missing

E-0095's first success criterion claims that an unattended `aiwf upgrade` in a consumer repository with no `guidance` configuration leaves it with `.guidance/`, an updated `guidance.packs`, host routing and a report naming what was adopted. M-0353/AC-2 asks for that run to be observed in a real consumer repository, and passes on that outcome or on a report naming a handover blocker and its fix. Only a hermetic stand-in backs either: `TestBinary_UnattendedUpgradeAdoptsGuidance` in `internal/cli/integration/upgrade_cmd_test.go`. It replaces the `go` toolchain with a fake installer and the published catalogue at `https://github.com/23min/engineering-guidance.git` with a one-pack local catalogue, and it runs with no ai-dotfiles installation. The observation M-0353/AC-2 specifies has not been made.

M-0353 requires the observation to run against the released binary for the epic, and no release contains E-0095. Measured in the E-0095 epic worktree, where `bb0f480be` is the first commit on the epic branch that is not on `main`:

```
$ git merge-base --is-ancestor bb0f480be v0.38.0; echo $?
1
$ git tag --contains bb0f480be
$
```

## Why it matters

The hermetic test leaves out conditions the consumer repository behind E-0095 had: the published catalogue's real pack set and detection patterns, and an ai-dotfiles installation whose delivery must be handed over. Until the observation is made against the first release that contains E-0095, that release can be in use with upgrade adopting nothing in such a repository, or blocked on a handover whose reported fix does not clear it, and nobody has looked.

## Observation, 2026-10-23

The observation M-0353/AC-2 specifies, made against v0.41.0, the first release containing E-0095.

**Environment.** Linux 7.0.14-linuxkit x86_64 devcontainer, go1.25.12, at 2026-10-23T17:03Z. Consumer: a fresh clone of `github.com/23min/loom` at `7547d6602`, a Rust workspace with Dafny models and TLA+ specifications, whose `aiwf.yaml` has no `guidance` block and which has no `.guidance/`. Its `CLAUDE.md` carries an `ai-dotfiles:stack` block generated by `dotfiles-sync`, importing `~/.agents/guidance/206-rust.md`, `207-dafny.md` and `208-tla.md`. The machine has no ai-dotfiles installation as `projectguidance.CheckCompatibility` detects one: neither `dotfiles-sync` nor `dotfiles-guidance-check` is on `PATH` or in `~/.local/bin`, `~/.claude/CLAUDE.md` is absent, `~/.codex/AGENTS.md` mentions neither `ai-dotfiles` nor `.agents/guidance/`, and `~/.agents/` does not exist. The run therefore exercises adoption and the removal of the repository's legacy import, not a handover blocker. The starting binary is v0.40.0, installed into a private `GOBIN`, because `upgrade` returns "already at target" without running `update` when the binary is at the release it targets.

**Command.**

```sh
export GOBIN=<scratch>/bin
go install github.com/23min/aiwf/cmd/aiwf@v0.40.0
cd <scratch>/consumer
aiwf upgrade --root . </dev/null
```

**Expected.** `upgrade` installs v0.41.0 and re-executes its `update`, whose Guidance section names the adopted packs; the clone is left with `.guidance/`, `guidance.packs` in `aiwf.yaml` and engineering-guidance routing in its host instructions.

**Observed.** Exit 0. The output, with the step ledger shortened to the guidance lines:

```
current:  v0.40.0 (tagged)
target:   v0.41.0 (tagged)
status:   upgrade available

running:  go install github.com/23min/aiwf/cmd/aiwf@latest
re-exec:  <scratch>/bin/aiwf update --root <scratch>/consumer
Hosts (detected): claude-code, codex
  ...
  created    AGENTS.md (guidance)  (wired native guidance)
  updated    .guidance (project engineering guidance)  (selected project guidance at 9c9ca4b3681ca4cb8798e5af9e9124b1e761526b)
  ...
aiwf update: done.

Guidance:
  selected:  code-health, rust/edition-2024-workspace, dafny/z3, tla/tlc
  adopted:   code-health, rust/edition-2024-workspace, dafny/z3, tla/tlc
  installed: code-health, rust/edition-2024-workspace, dafny/z3, tla/tlc at 9c9ca4b3681ca4cb8798e5af9e9124b1e761526b
  ignored:   none
```

Afterwards `aiwf.yaml` gains `guidance: packs: [code-health, rust/edition-2024-workspace, dafny/z3, tla/tlc]`; `.guidance/` holds `index.md`, `.aiwf-owned` and a guide for each pack; `CLAUDE.md`'s `ai-dotfiles:stack` block is replaced by the `aiwf:engineering-guidance` routing block, and a new `AGENTS.md` carries the same block. `aiwf doctor` reports both hosts' guidance `ok`, the same four packs selected, and installed revision `9c9ca4b36…`.

## Observation with a legacy ai-dotfiles installation, 2026-10-23

The handover arm of M-0353/AC-2, in the same devcontainer on the same day, with `github.com/23min/ai-dotfiles` installed by its own `install.sh` into a scratch `HOME` (`CLAUDE_CONFIG_DIR` and `CODEX_HOME` unset; `PATH` led by that home's `~/.local/bin`, then the directory holding the `claude` and `codex` launchers, which holds no ai-dotfiles tool). Two ai-dotfiles commits are used: `2552653` (2026-08-03), which ships `dotfiles-sync` and no `dotfiles-guidance-check`, and `934db4a` (2026-09-22), the last before ai-dotfiles dropped assistant delivery, which ships the checker. The consumer is a fresh clone of loom at `7547d6602` as above.

**Blocked.** With ai-dotfiles at `2552653`, the install leaves `~/.local/bin/dotfiles-sync` and a `~/.claude/CLAUDE.md` importing `~/.agents/guidance/`. Command: v0.40.0 into a private `GOBIN`, then `aiwf upgrade --root . </dev/null` in the clone. Expected: the report names the handover blocker and its fix, and nothing is half-installed. Observed: exit 0; `upgrade` installs v0.41.0 and re-executes `update`, which detects `claude-code, codex` and ends:

```
Guidance:
  selected:  not adopted (guidance.packs unset)
  adopted:   none
  installed: none
  ignored:   none
  blocked:   incompatible ai-dotfiles guidance delivery: detected <home>/.claude/CLAUDE.md but dotfiles-guidance-check is unavailable; update/reconcile ai-dotfiles and make its checker available on PATH, then retry
```

No `.guidance/` is created, `aiwf.yaml` gains no `guidance` block, and `CLAUDE.md`'s `ai-dotfiles:stack` block is left in place. `aiwf doctor` on the same clone reports `selected: not adopted (guidance.packs unset)` and `installed revision: unknown (no intact owned index)`, and names no blocker.

**Following the fix.** Checking out `934db4a` and rerunning `install.sh` exits 1 with ai-dotfiles' own refusal: `<home>/.agents/AGENTS.md still supplies legacy or unreconciled global guidance; prepare dependent repositories with dotfiles-sync, then rerun with --personal-only to confirm they are prepared; nothing replaced`. Following that, `dotfiles-sync` in the clone rewrites the stack block to `Read .ai-dotfiles/engineering.md for this repository's engineering guidance.` and writes `.ai-dotfiles/`; `install.sh --personal-only` then exits 0, and `dotfiles-guidance-check` reports `ai-dotfiles personal-only delivery is compatible in this environment` at exit 0. A second `aiwf update --root . </dev/null` exits 0 with `selected`, `adopted` and `installed` naming `code-health, rust/edition-2024-workspace, dafny/z3, tla/tlc` at `9c9ca4b36…` and no `blocked` line; `CLAUDE.md`'s `ai-dotfiles:stack` block is replaced by the `aiwf:engineering-guidance` block, and `aiwf doctor` agrees with the report. The `.ai-dotfiles/` directory `dotfiles-sync` wrote stays in the clone, with no route in `CLAUDE.md` or `AGENTS.md` naming it.
