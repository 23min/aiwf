## What's missing

Two live surfaces state different rules for the same act — reconciling a
consumer-owned ordering file against tree state — and nothing reconciles them.

`internal/skills/embedded-rituals/plugins/aiwf-extensions/skills/aiwfx-whiteboard/SKILL.md`
under *Keep the ordering* names `TODO.md` as the example and prescribes:

> Drop entries whose entities are terminal, and any cluster that has emptied.
> Mechanical — no need to ask.

This repo's own `TODO.md` preamble prescribes the opposite for that act:

> Claude may reconcile *Next, in order* against live tree state and propose a
> delta — terminal entries dropped, new entities placed, moves justified — and
> writes only what you accept.

Measured 2026-08-26: a reconcile run against the file's own rule proposed the
delta and waited; the skill's rule authorises the same drops with no prompt. Both
surfaces ship, neither cites the other, and a reader reaching either one finds a
complete-looking instruction.

A second site states a false premise about the same file. `wf-doc-lint`'s
SKILL.md excludes a consumer `TODO.md` from lint scope as *"regenerated by a
project tool … if it drifts, the fix is to regenerate the source, not to file a
lint finding."* No tool regenerates this repo's `TODO.md`; its preamble declares
it a hand-authored scratchpad replaced wholesale by an accepted delta, and there
is no source to regenerate. The exclusion is right; the reason given for it is not.

## Why it matters

The file's design is that it needs no external machinery: it carries its own
instructions and nothing in code, tests, CI or `aiwf.yaml` reaches it — verified
2026-08-26, and adding it to `docs.paths` was measured and ruled out on
2026-08-25 as reaching nothing. A second copy of its instructions in a shipped
skill defeats that design, because the copy is what a session reads when it loads
the skill rather than the file.

The divergence is not cosmetic. One rule requires an approval gate before entries
are dropped; the other removes it. Which of the two a given session follows
depends on whether it opened the file or loaded the skill.

## Resolution shape

The open question is genuine rather than mechanical: the whiteboard skill ships
to consumer repos whose ordering file may carry no preamble at all, so it cannot
simply defer — it needs a default. What has to be decided is whether a preamble,
where one is present, overrides that default, and how the skill says so without
restating what the preamble holds.

Both sites sit under `internal/skills/embedded-rituals/`, so an edit is subject to
`skill-edit-structural-test-backstop`. D-0050 governs what that test may assert,
and G-0606 leaves the standing of phrase-pins over shipped prose undecided, so the
backstop must be satisfied structurally.
