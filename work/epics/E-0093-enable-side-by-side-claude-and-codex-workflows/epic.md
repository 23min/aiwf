id: E-0093
title: Enable side-by-side Claude and Codex workflows
status: active

## Goal

Make aiwf usable from Claude Code and Codex in the same local repository, with
automatic setup for installed hosts, straightforward handoff between assistants,
and parallel implementation in separate worktrees.

## Context

aiwf embeds canonical workflow definitions and implements Claude and Codex
artifact generation, including native Codex guidance, behind its internal target
boundary. Public initialization, refresh, diagnosis, guidance wiring, and worktree
setup still select Claude; automatic detection and public host selection remain
the scope of M-0342.
The local container can now run Codex, and a source-built aiwf binary has created
the isolated `feat/codex-support` worktree for implementation.

The agent-host artifact adapters initiative captures the scope and agreed
contracts. A planning probe demonstrated deterministic characterization of
generated Claude paths, modes, and bytes across independent roots and repeated
initialization. Permanent compatibility tests precede renderer changes.

## Scope

- Detect executable Claude and Codex commands on the invoking process's PATH
  during init/update and use the same resolver for doctor and aiwf-created
  worktrees. Upgrade inherits this behavior through its update re-execution.
- Treat an absent `hosts` field as automatic detection, an explicit supported
  list as an override, and an explicit empty list as no host output. Preserve
  this distinction through configuration reads and writes; reject unknown hosts.
- Materialize every selected host in one invocation. A host disappearing from
  PATH or being deselected never implicitly deletes its installed files.
  Report selected, refreshed, retained, and conflicting artifacts distinctly.
- Render Claude and Codex from canonical skill, template, and guidance sources
  using explicit placeholders and small named host fragments. Preserve existing
  Claude output except for the specified selection and symlink corrections.
- Generate Codex skills under `.agents/skills/`, shared templates under
  `.agents/aiwf/templates/`, and concise guidance directly in a marker-managed
  root `AGENTS.md` block, automatically maintained with a persistent opt-out.
- Preserve user content and foreign artifacts, diagnose malformed markers and
  ownership collisions, and skip guidance writes through symlinks for both
  hosts. Diagnose aliased instruction paths before either writer changes them.
- Make lifecycle ledgers, dry-run, installation-health checks, schema, examples,
  and help consistent with effective host selection. Diagnose content drift
  against the same rendered definitions used by the writers.
- Adapt operational instructions for Codex, including worktree selection and
  required independent review. Verify a usable delegation path without requiring
  conversion of the Claude custom-role file corpus.
- Dogfood in this repository's devcontainer and provide its development
  instructions to Codex without maintaining an independent copy of the rules.
  Verify host switching and simultaneous sessions in separate worktrees.

## Out of scope

- Codex cloud/review distribution, Codex-managed worktrees, lifecycle-hook
  integration, custom-role TOML parity, and statusline parity.
- New entity kinds, FSM changes, planning-state migrations, or a second workflow
  engine. The existing aiwf commands remain the authority for both hosts.
- Automatic transcript transfer, cross-worktree synchronization, or parallel
  TDD orchestration from E-0019.
- Renaming `.claude/worktrees/`; the existing `worktree.dir` remains configurable
  and its location is usable by either host.
- The general guidance-reduction project E-0092, a universal delivery mechanism
  for G-0523, or a stale-binary downgrade guard for G-0600.
- Following symlinked instruction files or automatically removing deselected
  host installations. Both require separate explicit contracts.

## Constraints

- One canonical source for workflow facts. No independent Claude and Codex
  corpora, prose-based search/replace rules, speculative plugin architecture,
  or new runtime dependency.
- Resolve and validate host selection and rendering before artifact writes.
  Rendering errors name the source, placeholder or fragment, and selected host.
- Preserve Claude's existing paths, generated bytes, and consent behavior for
  ordinary files. Automatic detection and preserving symlinks are explicit
  behavior changes; preserve the shared atomic writer's existing contract.
- Keep core Git hooks host-independent. Claude-only hooks, settings, and
  statusline operations must not run for Codex-only or no-host selections.
- Restrict changes to owned paths and managed blocks. Atomic file writes and
  idempotent recovery do not imply a transaction across the entire artifact set.
- Follow accepted D-0070: test output behavior, generated relationships, and
  derived expectations rather than asserting the presence of prose phrases.
- Use TDD for new logic and exercise every reachable changed branch. Run the
  repository's build, lint, race, coverage, and selfcheck gates before release.
- Planning is recorded on main per D-0073. Implementation occurs in the isolated
  worktree after approved planning commits are integrated there. Commits, shared
  merges, pushes, and rebuilds retain their respective approval boundaries.
- Use a binary built from the implementation checkout for validation. Git hooks
  and installed binaries can be shared across worktrees; separate sessions do
  not make those resources independent.

## Success criteria

- [ ] A consumer running init/update receives complete local artifacts for the
  detected hosts, or the explicit override, with actionable reporting when
  neither host is available.
- [ ] Installing the second host and rerunning update adds its usable surface
  without damaging the first host or changing user-owned instruction content.
- [ ] Explicit Claude selection retains the characterized ordinary-file
  behavior; a symlinked instruction file is preserved and a skipped update is
  clearly diagnosed.
- [ ] A Codex-only consumer can discover the skills, obtain standing guidance,
  resolve templates, and perform a representative workflow with independent
  review without translating Claude artifacts by hand.
- [ ] Doctor distinguishes missing, stale, conflicting, and unselected retained
  artifacts using the same host selection and rendered expectations as refresh.
- [ ] Fresh-session evidence demonstrates Claude-to-Codex-to-Claude handoff and
  concurrent work in separate branches/worktrees without unintended cross-edits.
- [ ] The devcontainer's install and persistence setup has a recorded rebuild
  verification, and the supported local capability boundary is documented.

## Open questions

| Question | Blocking? | Resolution path |
|---|---|---|
| Does current Codex delegation satisfy each supported ritual's independent-review requirement? | Blocks claiming workflow compatibility | Validate the rendered instructions in the adapter milestone and exercise a fresh reviewer in the live-session milestone. Report unsupported operation rather than weakening review. |
| Are live Claude access and a container rebuild available during validation? | Blocks epic closure, not implementation | Record actual session and rebuild results when available; an unrun check stays outstanding. |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Shared rendering changes Claude behavior | High | Characterize output before refactoring; explicitly isolate the detection and symlink policy changes. |
| Guidance or ownership handling damages user files | High | Preflight conflicts, preserve surrounding bytes and links, reject unsafe ownership paths, and exercise foreign-content fixtures. |
| Detected tools vary between terminals, containers, and CI | Medium | Explicit overrides, visible resolution, deterministic test inputs, and non-destructive retention. |
| Generated files exist but the host does not load them | High | Test fresh sessions and exposed discovery surfaces; do not equate presence or model narration with guaranteed delivery. |
| Different sessions use different aiwf binaries | Medium | Use a source-built binary consistently and disclose shared-hook behavior; do not claim general downgrade protection. |
