## Goal

Introduce a tested rendering boundary for shared workflow sources while preserving the existing Claude artifact output and public host-selection behavior.

## Closes

- (none)

## Context

The current materializer copies embedded Markdown and routes paths through a Target value. E-0093 requires explicit placeholders and named fragments before Codex output is enabled. A planning probe has demonstrated deterministic paths, modes, and bytes for the existing materializer; permanent regression checks remain to be added.

## Acceptance criteria

The criteria below define the observable completion contract.

### AC-1 — Claude output and consent behavior match the pre-refactor baseline

Capture the baseline before changing canonical sources. Compare the complete owned-artifact inventory, relative paths, file modes, and generated bytes for ordinary Claude setup, refresh, and aiwf-created worktrees. Exercise existing configuration and hook-consent choices, surrounding user instructions, and foreign files. Keep the expected baseline independent of the new renderer so a common writer/expectation defect cannot pass by construction. Evidence is deterministic filesystem and CLI behavior, not checks that prose contains particular phrases.

### AC-2 — Explicit bindings render deterministically and reject invalid inputs

Render representative paths and named host fragments from a closed typed contract. The same source and bindings produce identical bytes; text outside explicit substitution sites is preserved. Unknown placeholders, unknown fragment names, missing host bindings, and invalid template syntax return errors naming the source and missing input before materialization writes files. Exercise each reachable error and success branch without using installed host tools or the network.

### AC-3 — Claude consumers use rendered definitions without unresolved placeholders

Route current Claude materialization and its existing expected-content checks through the rendering boundary. Compare generated files against independently established baseline bytes and verify that skill frontmatter remains parseable and generated local references resolve. A file containing a known unresolved rendering token is a failure. Do not introduce general prose bans or treat legitimate configured paths such as .claude/worktrees as Codex-incompatible by spelling alone.

### AC-4 — Independent roots and repeated refreshes produce equivalent artifacts

Materialize the same version and configuration in independent temporary repositories, then refresh each again. Compare relative path inventories, modes, and content; preserve surrounding user bytes and unrelated artifacts. Include init, shared refresh, and aiwf-created worktree entry points. Exclude only explicitly identified runtime metadata, such as health timestamps, from byte equivalence; do not normalize away unexplained differences.

## Constraints

- Author shared workflow facts once; use explicit typed bindings and small named fragments only for host differences.
- Do not expose Codex selection or change the default host behavior in this milestone.
- Preserve Claude output for ordinary owned artifacts. Later milestones carry the explicit host-selection and symlink policy changes.
- Test filesystem and rendering behavior under D-0070; do not add literal prose-presence tests or rely on proposed D-0072 as accepted policy.
- No new runtime dependency or extensible plugin framework. Exercise all reachable new rendering branches with deterministic inputs.
