Use an aiwf-created worktree for this workflow. Codex's experimental managed-worktree feature is not required; Codex-managed creation is outside aiwf's supported workflow, and artifact availability there must be established separately.

Use the printed checkout path as the explicit working directory of each shell/tool call. If the shell interface has no working-directory argument, prefix each command with `cd "<printed path>" &&`; do not assume a previous call's `cd` persists. Root file edits in that checkout and verify its branch before mutations. At wrap, explicitly target the worktree holding the merge destination. To start a fresh Codex CLI session with the new checkout's instructions and skills, use `codex -C "<printed path>"`. When continuing in an existing session, explicitly read its `AGENTS.md` and relevant skills; changing a tool working directory does not reload session instructions or skill discovery. If the path is outside the current session's permitted filesystem, report that limitation and use a session configured for that checkout.
