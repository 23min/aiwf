title: Declare document authority in aiwf.yaml, not frontmatter

> **Date:** 2026-08-16 · **Decided by:** human/peter

## Context

Three surfaces in this repository state which documents carry authority, and two
of them disagree about the same file.

- **`CLAUDE.md`'s `## Documentation hierarchy`** assigns four authority tiers to
  active `docs/` subtrees, so a reader can weight a file from its path alone.
  It is prose, it is scoped to `docs/`, and it has no vocabulary for a generated
  file.
- **`aiwf.yaml`'s `docs.paths`** names the repo-facing prose the kernel scans,
  per consumer, with `docs.strict` raising its findings to blocking. It names
  `README.md`. The hierarchy does not mention that file at all.
- **The preflight initiative's corpus table** classifies the tracked root
  documents by hand — hand-authored against derived against append-only —
  because the hierarchy could not supply it.

Each states a fact about the same subject, and nothing derives one from another,
which is the duplication [D-0054](../../work/decisions/D-0054-keep-the-reasoning-derive-the-facts-record-obligations-not-events.md)
bans. [G-0589](../../work/gaps/G-0589-the-doc-authority-tiering-leaves-root-and-derived-documents-unclassified.md)
records the fork and names where the next one lands: a shipped review pass has to
tell a reviewer what to read, and its only options are a hierarchy that omits the
root files, or a fourth copy of the classification.

A path-based tier is also wrong about files inside the subtrees it names, not
merely silent about the ones outside them. `docs/design/legal-workflows-audit.md`
and `docs/design/legal-workflows-first-principles.md` are the Pass A and Pass B
working artifacts of [ADR-0011](ADR-0011-legal-workflow-spec-methodology.md)'s
three-pass methodology, kept so the reconciliation they fed stays auditable. The
audit catalog says in its own header that it is not the spec and not the source of
truth for what aiwf permits. Both sit under `docs/design/`, which the hierarchy
assigns to Normative — current truth, kept in lockstep with the code. The tier and
the document contradict each other, and the tier is what a reader sees first: a
reviewer weighting those files by path reads their dated rule statements as stale
current-truth and proposes correcting them, which would destroy the record they
exist to hold. `PolicyM0128DocumentationHierarchy` reports nothing either way,
because it asserts the section's shape and never opens a file. A declared list
expresses the exclusion a subtree cannot — the two files are simply not on it.

The question is now load-bearing rather than editorial. A review pass that audits
a specification against what the project has committed to must decide which
documents bind; `wf-doc-lint` reports drift against documents nothing designates;
and [G-0560](../../work/gaps/G-0560-the-normative-doc-tree-has-drifted-from-the-kernel-it-documents.md)
tracks normative documents having drifted from the kernel, which presumes a
settled answer to what is normative. No ADR or decision supplies one.

**The alternative on the table is a per-document frontmatter marker** —
`normative: true`, proposed in two captured initiative documents. Three things
decide against it.

A generated file cannot declare itself. `ROADMAP.md` is regenerated by
`aiwf render roadmap`; a marker inside it must be emitted by the renderer and can
be flipped by a hand-edit, so the one classification a reader most needs to trust
is the one the scheme holds least reliably. The project has to say "this file is
output", and that is not a statement the file can make about itself.

Authority is a project's claim, not a document's. A marker lets any edit promote
any file, which inverts where the claim belongs.

And a fresh consumer repository has no marked documents, so a frontmatter scheme
reads nothing until every file has been visited. A configured list has a default
and one place to change.

## Decision

A project declares document authority in `aiwf.yaml`, under the existing `docs:`
block, and not in document frontmatter. Two classifications, both lists of
repo-relative paths:

- **normative** — documents the project maintains as current truth.
- **derived** — documents regenerated from another source, where a contradiction
  is a stale render rather than a claim about the project.

`docs.paths` keeps its current meaning and is not overloaded: it selects the
prose the id-shape rules scan, which is a different question from what binds.

**An undeclared project is not a broken one.** With no classification present, a
reader falls back to describing the corpus by property — documents the project
maintains as current truth, excluding generated output and archived snapshots —
and proceeds. Configuration sharpens that default; it is not a precondition for
using any surface that needs the answer.

`CLAUDE.md`'s `## Documentation hierarchy` becomes prose that explains the
classification rather than a second registry of it.

## Consequences

One machine-readable answer exists, so a shipped surface can point at it instead
of restating it. That is what closes the fork G-0589 names, and it is available
to `wf-doc-lint` and to any review pass on the same terms.

A check can verify that every declared path is tracked and exists. It cannot
verify that the list is complete — no mechanism can, since completeness is the
judgment about what the project means to bind. Stating that here is what stops a
future reader treating a clean check as proof the classification is right.

Consumers who configure nothing keep working, which is what makes this shippable
rather than a migration.

The cost is two config keys with their unknown-key guard and defaults, and a
`CLAUDE.md` section that shrinks to explanation. The drift risk that
[G-0092](../../work/gaps/archive/G-0092-no-documented-doc-authority-hierarchy.md)
closed without addressing moves onto a surface a check can reach, though building
that check is not part of this decision.

## Validation

The signal is a fourth surface. If any shipped artifact, ritual or document
states the classification again rather than reading it, this decision has not
held and the reason is worth knowing before adding more machinery.
