# Scope lifecycle: what the history and the code show

Machine `scope`: one agent's delegation on one milestone. This file records what the commits, the entities they cite, the code at HEAD and runs of the built binary show for each case. It does not say which claim is right.

## Evidence read

- **Commits.** Every commit touching the 25 lifecycle files listed in the brief (252 commits, 2026-05-05 to 2026-11-08), the commits touching the same files at their earlier paths under `tools/` before the reorg in a13713213 (66 commits, from 2026-04-26), and the commits touching the intermediate `cmd/aiwf/` copies (`authorize_cmd.go`, `provenance.go`, `scopes.go`, `show_scopes.go`, `show_cmd.go`, `import_cmd.go`) between the reorg and their moves (9 commits). That makes 327 commits. Each was screened by subject, message and the scope-related lines of its diff on those files. The 64 that touched scope behaviour were read in full (message plus diff).
- **Cited entities, read as they stood at the citing commit:** `G22` (an entry in `docs/pocv3/gaps.md` at 22d7c63e0, later renumbered G-0022), G-0119 and G-0120 at a87d7138b, D-0014 at 0a8a6bf1e, D-0007 at d5abcf51b, M-0106 at 03ceea8b3, G-0206 and G-0225 at a744c873b, M-0325 and G-0460 at 00012965f, G-0329 at 08b20a0ac (searched for scope or rebase mentions only).
- **Not read:** ADRs and design docs, at any revision (ADR-0010, ADR-0013, ADR-0036, ADR-0047 and the provenance model are cited by commits but excluded by the brief). GitHub issue #5, cited by c5b6ab770, could not be read: the project has no issue tracker, and that commit concerns the untrailered-commit audit range, not the scope FSM.
- **Code:** HEAD cc0d64cff (2026-11-21).
- **Runs:** the binary was built from this worktree at cc0d64cff with `go build -o "$S/aiwf" ./cmd/aiwf`, Go 1.25.12 linux/amd64, in the Linux devcontainer on 2026-11-21. `aiwf version` printed `v0.42.1-0.20261121183124-0c00b37c47b3+dirty`. Every run used a disposable repo under a scratch directory, with `git config user.email t@example.com`, so the actor is `human/t`. Fixture: `aiwf.yaml` with `hosts: []`, then `aiwf init`, `aiwf add epic --title "Engine"`, `aiwf add milestone --epic E-0001 --title "First milestone" --tdd none`, two ACs added, and `aiwf promote E-0001 active`. Fixture "base2" adds AC bodies (`aiwf edit-body`) and `aiwf promote M-0001 in_progress` on branch `epic/E-0001-engine`. The ids E-0001 and M-0001 in run output name entities in those disposable repos, not in this repository. Hand-made commits were written with `git commit --allow-empty --no-verify` and the stated trailers, to stand in for history no verb would write.

## 3. Conflicts

Each entry is a case on which two claims disagree and neither is a later change to the other.

1. **Replay of a hand-written pause or resume with no scope in the source state** (for example, resume while active). `LoadScope` refuses the history as malformed (H5). The replay production uses ignores the commit silently (H56). Both are in the code at HEAD; `LoadScope` has no production caller (H57).
2. **ended, rebase.**
   - The scope FSM says ended is terminal and needs a new authorization (H4, H57). M-0325 says nothing undoes an end (H48).
   - After a rebase, run rb2 shows the operator-ended scope active again under its new SHA, the agent acting under it, and check silent (H77), because ends match by exact SHA (H58).
   - f56d7073b relies on check's read-time resolution to handle rebases (H21). That pass catches a stale `aiwf-authorized-by` (H75) but not this case.
3. **closed, rebase.** The same claims (H4, H48, H49) against run rb3: after a rebase, a done milestone carries an active scope, which pause and end then act on (H78).
4. **closed, authorize `--force`, then pause, resume or act.** 00012965f and the current doc on `loadEndableScopeAuthSHAsForEntity` say no verb acts on a terminal entity again (H49). The force path in place since 3b573c77a (H9) lets a scope open on a done milestone, after which pause, resume and an agent act all succeed (H73).
5. **paused, act.** The verb refuses an agent act (H12, H64). Check accepts a commit made in that state: no rule reads pause state (H59), and run p reports no error (H74). The two claims come from different surfaces.
6. **none, act by a `bot/` actor.** The allow rule covers "ai/... or bot/..." and the verb refuses (H11, H84). Check's no-active-scope rule tests only `ai/` and reports nothing (H61, H84).
7. **active, authorize repeated with the same arguments.** G-0460 leaves open whether two active scopes on one milestone are legal, and proposes a refusal plus a check rule as one resolution (H50). The code opens the second scope and reports nothing (H8, H66). No commit in the read set carries out a resolution.
8. **active or paused, end, between 2026-05-02 and 2026-08-29.** In that window, scopes could not be ended without closing the milestone (H15).
   - The authorization-ended hint named "revoke" as a way scopes end (H20).
   - G-0225 named an `authorize-end` event and offered "ended and re-authorized" as a remedy (H39).
9. **authorize `--force` on a gap, decision, contract or ADR.** D-0007 says `--force` overrides the kind refusal (H26). The code refuses before reading `--force`, and run g confirms it (H25). This case never arises for a milestone.
10. **active, check of an agent commit on an AC off its bound branch.** M-0106 says `isolation-escape` fires for commits made under an active scope on the wrong branch (H36). The code keys openers by exact `aiwf-entity`, so AC-level commits are never policed (H60). Run ie shows a milestone-level commit flagged and an AC-level commit on the same branch not flagged (H85).
11. **any, agent act through `aiwf import`.** The verb applies no scope gating (H16). Check flags every `ai/` commit lacking `aiwf-on-behalf-of` (H18), and import stamps only `aiwf-principal`. Not run: `aiwf import --actor ai/claude --principal human/t <manifest>` followed by `aiwf check --since main` would settle whether check flags each imported commit.
