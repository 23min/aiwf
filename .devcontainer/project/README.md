# aiwf's own container setup

`.devcontainer/` is generated by the house devcontainer kit; `../README.md` describes what the
kit provides. This file covers what aiwf adds on top, in the files the kit leaves to the repo:
this folder and a few commented hand edits in `devcontainer.json`.

The container is where aiwf is developed. On Linux the macOS failures that bite the host path —
the fork/exec deadlock under `-race` with parallel tests, and syspolicyd crashes on unsigned
binaries — do not occur, so `make ci` runs as CI does. The host path stays available through
`scripts/sign-and-run.sh` (see `CLAUDE.md`, "Running tests on macOS host").

## What the project hook adds

`post-create.sh` in this folder runs once, after the kit's own post-create:

- pinned Go tools: golangci-lint, govulncheck and gitleaks at the versions CI runs, plus gofumpt
  and goimports;
- `aiwf`, built from this checkout with `go install ./cmd/aiwf` rather than a released version,
  then `aiwf init` for its framework files;
- `make install-hooks`, the kernel's pre-commit chain;
- Playwright, only when opted in (below).

It runs once per container, so the `aiwf` it installs reflects the checkout at creation. After
changing aiwf's code, rebuild it with `go install ./cmd/aiwf`, or use `make diag-aiwf` for a
binary scoped to the working tree.

Check a new container with:

```sh
aiwf doctor      # the rituals line confirms aiwf's files are in place
make ci          # the full local gate
```

## Environment variables

| Variable | Set by | Effect |
|---|---|---|
| `GOTOOLCHAIN` | `devcontainer.json` `containerEnv` | Pins Go to `GO_VERSION` in `.github/workflows/go.yml`, so the container builds with CI's Go. A policy test keeps the two equal. It takes precedence over the kit's note that `go.mod` pins Go. |
| `AIWF_DEVCONTAINER` | `devcontainer.json` `containerEnv` | Always `1`; `aiwf doctor` reads it to report that it runs in this container. |
| `AIWF_DEVCONTAINER_E2E` | you, for a rebuild | `true` makes the project hook install Playwright (below). Unset means `false`. |

## Playwright tests

The HTML renderer's end-to-end tests under `e2e/playwright` need Node packages and Chromium
(about 100 MB), so the container leaves them out by default.

- In a running container, install them with `make e2e-install`, then run `make e2e`.
- To have container creation install them, set `AIWF_DEVCONTAINER_E2E=true` in
  `devcontainer.json`'s `containerEnv` on your machine (do not commit it), then run
  **Dev Containers: Rebuild Container**.

## Recovery

When a step of container creation fails, VS Code runs no post-start, so the container lacks
Codex and the kit's per-start refresh, and the failed step's own work is missing. The kit's
post-create names the failed step and the command that finishes the job. Fix the cause, then run
in the container, from the repository root:

```sh
bash .devcontainer/post-create.sh && bash .devcontainer/post-start.sh
```

Both scripts are safe to re-run.

## Sibling repositories

The container mounts only this repository. To work on another repository alongside it, add it to
the kit's answers, read-only or writable, and rebuild:

```sh
uvx copier update --defaults --data 'siblings=[other-repo]'
uvx copier update --defaults --data 'writable_siblings=[other-repo]'
```
